# FIXES V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the committee's real 83-member ministry roster and the full events page — three new upcoming events, three past events, and no "Read more" link on event cards.

**Architecture:** This is an Astro 5 content-collection site with no database. Almost all of this change is content: one YAML file for the roster and sixteen Markdown files (eight events × two languages). Two small code changes support it — an optional `dateTbd` flag on the events schema so "CUTES Christmas Caroling" can publish without a date, and the removal of the read-more anchor from `EventCard.astro`. The events page already renders an "Upcoming"/"Past events" split driven by `splitEvents()` against the build date, so the Past Events section the committee asked for needs no new code, only events whose dates have passed.

**Tech Stack:** Astro 5, TypeScript, Tailwind CSS v4, Zod content schemas, Vitest, Node ≥ 20.3.

**Spec:** `docs/superpowers/specs/2026-09-28-fixes-v2.md`

## Global Constraints

- All commands run from `D:\Project\CUTES\Website` — that is the npm project root. The repository root is `D:\Project\CUTES`.
- Committee-supplied copy is reproduced **verbatim** in English, including the past-tense phrasing on events that have not happened yet ("came together"). Do not rewrite it. Only the Bahasa Malaysia translations are authored.
- Every Markdown collection file lives at `src/content/<collection>/<lang>/<slug>.md`. Language comes from the folder, never from frontmatter.
- Every event needs both an `en/` and an `ms/` file with the **same slug**, or the BM route silently falls back to English.
- `location` is required by the schema. Where the committee gave no venue, use the codebase's existing convention for this: `TODO — venue` (English) / `TODO — tempat` (BM), matching the existing `location: TODO — retreat centre` in `src/content/events/en/retreat.md`.
- Do not change `site.diocese` in `src/data/site.ts`. It stays `'Archdiocese of Penang'`, asserted by `src/data/site.test.ts:16`. The committee's "Diocese of Penang" wording appears only inside the event copy that they wrote.
- `npm run build` runs `astro check` first; a schema violation or a type error fails the build. That is the acceptance gate for every content task.
- Today's date for the purposes of this plan is **2026-09-28**. "Past" and "upcoming" are decided at build time by `splitEvents()` in `src/lib/content.ts`, comparing `endDate ?? startDate` against the build date.

```ts
import { describe, expect, it } from 'vitest';
import { eventWhen } from './content';

/**
 * The committee sometimes announces an event before fixing its date. The
 * event still has to sort somewhere, so it keeps a placeholder startDate and
 * sets dateTbd — and every place that prints a date has to honour the flag,
```

```ts
/**
 * The date line for an event.
 *
 * An event whose date the committee has not fixed yet still needs a
 * `startDate` — it is what the schema requires and what `splitEvents` sorts
 * on — so it carries a placeholder one and sets `dateTbd`. Every place that
 * prints an event date goes through here, so the placeholder can never reach
 * the page.
 */
export function eventWhen(
  data: { startDate: Date; endDate?: Date; dateTbd?: boolean },
  lang: Lang,
  tbdLabel: string,
): string {
  return data.dateTbd ? tbdLabel : formatDateRange(data.startDate, data.endDate, lang);
}
```
